순서만으로 안 되는 것들

상태 조건 · 비동기 대기 · 권한 반전 — 카드를 순서대로 호출해도 여기서 막힙니다. 모두 서버 코드에서 확인한 규칙입니다.

토큰에는 역할이 없다

JWT payload는 iss/aud/sub/provider/iat/exp뿐입니다. 인가에 쓰는 역할은 요청마다 DB에서 조회합니다.

강사 승인→ 기존 토큰 그대로 INSTRUCTOR 적용
재로그인 필요 없음· 토큰 갱신은 만료 때만

⚠ 회차는 SCHEDULED로 태어난다

생성만으로는 출결을 못 엽니다. PUT /sessions/{sessionId}로 OPEN 전환이 별도로 필요합니다.

SCHEDULED→ PUT status=OPEN → OPEN→ QR 발급 가능
OPEN 아님→ 409 ATTENDANCE_CONFLICT
출결창 밖→ 409 ATTENDANCE_WINDOW_CLOSED · TTL 30초

⚠ completedMinutes는 받아올 곳이 없다

이수 평가가 요구하는데 어떤 응답에도 없습니다. 클라이언트가 서버 계산식을 재현해야 합니다.

회차 목록+ 회차별 출결→ PRESENT·LATE 회차의 → (endsAt − startsAt) 합
출결 요약 응답에 없음· 서버 로직 중복 구현 필요

⚠ 이수 평가 값은 지어낼 수 없다

서버가 출결 요약을 자체 계산해 요청 body와 대조합니다. 예시 숫자를 그대로 넣으면 실패합니다.

출결 요약 조회→ 그 값 그대로 → 평가 통과
임의 값→ 409 COMPLETION_METRICS_CONFLICT
전제→ 모든 회차 종료 또는 출결 마감 경과

⚠ 재발급은 폐기보다 먼저

재발급은 ISSUED에만 됩니다. 폐기한 뒤에 정정 발급하려 하면 막힙니다.

ISSUED→ reissue → 새 credentialId
REVOKED→ reissue → 409 CREDENTIAL_STATE_CONFLICT
202 PENDING→ polling → ISSUED/FAILED

Completion — ELIGIBLE 게이트

confirm은 평가가 ELIGIBLE이고 수강이 APPROVED일 때만 통과합니다.

평가→ ELIGIBLE→ confirm → COMPLETED
평가 전 조회→ 404 COMPLETION_NOT_FOUND

Enrollment — 취소와 철회는 시점이 다르다

cancel은 승인 전, withdraw는 승인 후에만 통과합니다.

APPLIED/WAITLISTED → approve· reject· cancel
APPROVED→ withdraw만 → WITHDRAWN

⚠ 정원이 차도 신청은 성공한다

정원 초과는 오류가 아닙니다. WAITLISTED로 접수되고 201이 돌아옵니다.

승인 수 < 정원→ 201 APPLIED
승인 수 ≥ 정원→ 201 WAITLISTED← 성공 응답

Course — RECRUITING에서만 신청을 받는다

모집 공개 전(DRAFT)이나 종료 후에는 수강신청이 409로 막힙니다.

DRAFT→ publish → RECRUITING→ close → RECRUITMENT_CLOSED
RECRUITING 아님→ 409 COURSE_STATUS_CONFLICT

⚠ 출결은 방식에 따라 호출 주체가 뒤바뀐다

같은 엔드포인트인데 attendanceMethod가 권한을 정합니다.

QR→ 본인만· 강사·관리자 403
수동→ 관리자·MAIN 강사만· 학습자 403
전제→ 같은 과정 APPROVED 수강· 회차당 1건
