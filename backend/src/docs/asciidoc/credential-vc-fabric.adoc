== Credential·VC·Fabric 인수 문서

Credential 8개 operation은 발급 요청, 상세·목록 조회, 폐기·재발급,
VC 문서 다운로드, 공개 검증, 검증 이력으로 구성됩니다. 발급·폐기·재발급은 `202 Accepted` 후 상세 조회로
`202 polling` 흐름으로 상태를 조회하며, 호출 범위와 `Idempotency-Key` 규칙은 각 operation 설명을 따릅니다.
Badge operation은 향후 구현 예정이며 현재 MVC handler는 구현하지 않습니다.

=== W3C VC 공개 리소스

외부 검증기는 인증 없이 아래 리소스를 조회할 수 있습니다. Context와 vocabulary는 `v1`
경로에서 의미를 고정하고, issuer 문서는 기관 식별 URL과 Ed25519 공개 JWK만 노출합니다.
개인키, 키 파일 경로, 사용자 정보는 반환하지 않습니다.

* `GET /api/v1/vc/contexts/lifelong-education/v1`
* `GET /api/v1/vc/vocabulary/lifelong-education/v1`
* `GET /api/v1/vc/issuers/{institutionId}`
* `GET /api/v1/vc/status-lists/{listId}`

폐기 여부는 W3C Bitstring Status List v1.0 으로 공개합니다. VC의 `credentialStatus`는
`BitstringStatusListEntry`이며 `statusListCredential`이 가리키는 리스트 VC를 받아
`statusListIndex` 번째 비트를 읽습니다. 리스트 하나가 발급기관 수료증 131,072장의 비트만
담고 개인정보·이수 정보는 담지 않으므로, 어느 수료증을 검증하는지 발급기관에 드러나지 않습니다.
인덱스는 발급 순서가 노출되지 않도록 무작위로 배정하고 재사용하지 않습니다. 응답은
`application/vc+jwt` Compact JWS이며 최대 60초 캐시할 수 있습니다.

=== Compact JWS 다운로드

`GET /api/v1/credentials/{credentialId}/document`는 기존 Credential 상세 조회와 같은 권한을
요구합니다. 발급 완료 계열 상태에서만 저장 Envelope·SHA-256·Ed25519 proof를 재검증한 뒤
Wrapper 없는 Compact JWS를 `application/vc+jwt` attachment로 반환합니다. 응답에는
`Cache-Control: no-store`가 적용됩니다.

=== 공개 Credential 상태

`GET /api/v1/vc/status/{credentialNo}`는 실제 `fabric` 프로필과 Fabric 연결이 활성화된 경우에만
인증 없이 검증 결과를 조회합니다. 원장 검증 서비스가 없으면 503을 반환하며 Fake Gateway 결과를
공개 상태로 사용하지 않습니다. 응답 필드는
`credentialNo`, `status`, `checkedAt`만 허용하고 DB·proof·Fabric 검증과 감사 기록은 기존
검증 서비스를 재사용합니다. 찾을 수 없는 번호도 개인정보 추측을 막기 위해 HTTP 200의
`NOT_FOUND` 상태로 반환하며 응답에는 `Cache-Control: no-store`가 적용됩니다.

=== 공개 검증

인증 없이 `credentialNo` 또는 64자리 `credentialHash` 중 정확히 하나만 제출합니다. raw
VC/proof는 받지 않고, proof·저장 hash·payload binding·상태·유효기간·Fabric read를 모두
통과해야 `VALID`입니다. 장애는 `ERROR`로 기록하며 성공으로 추정하지 않습니다.
